# AgroShift | أجروشيفت

**منصة زراعية ذكية لتحليل المناخ ودعم إدارة الحقول والدورات الزراعية في مصر.**

AgroShift تطبيق Flutter موجّه للمزارع والمهتمين بالإدارة الزراعية. يربط سجلات الطقس اليومية بموقع الحقل، ويعرض مؤشرات مناخية وزراعية مع توضيح مصدر البيانات وحدودها، إلى جانب إدارة الحقول وتقييم تسلسلات المحاصيل.

> **نطاق التطبيق:** المخرجات أدوات دعم قرار مبنية على بيانات مناخية ومعاملات محصولية مرجعية؛ وليست بديلاً عن القياسات الحقلية أو توصيات مهندس زراعي محلي. كما أن ETc المعروض ليس تلقائياً كمية الري الفعلية الواجب ضخها.

## الوظائف الرئيسية

يعرض التطبيق خمس وجهات رئيسية باللغة العربية، مع دعم إعدادات الترجمة للإنجليزية:

| الواجهة | الوظيفة |
|---|---|
| **الرئيسية** | لوحة متابعة الحقل المحدد، وملخصات الطقس والمؤشرات الزراعية والتنبيهات المتاحة. |
| **المناخ** | استعراض السجلات التاريخية للحقل، ومخططات درجات الحرارة العظمى والصغرى، وبيانات ET₀ مع إظهار حالات نقص البيانات. |
| **الدورات** | مختبر لتقييم تسلسلات ومحاصيل الدورة الزراعية باستخدام إعدادات التقييم الموجودة في التطبيق. |
| **الحقول** | تسجيل الحقول وإدارتها، وتحديد المساحة ونوع التربة والمحصول وتاريخ الزراعة، واختيار الموقع على خريطة مصر. |
| **المنهجية** | عرض المنهجية والمراجع العلمية والتنبيهات المتعلقة باستخدام المؤشرات والبيانات. |

### إدارة الحقول والمواقع

- تسجيل حقول زراعية مصرية وحفظ بياناتها محلياً.
- تخزين المحافظة والإحداثيات والمساحة بوحدة الفدان ونوع التربة.
- ربط الحقل بمحصول قائم وتاريخ زراعة عند توفرهما.
- اختيار الموقع من خريطة تفاعلية.
- التحقق من وقوع النقطة داخل الحدود الجغرافية المصرية، وتحديد المحافظة من بيانات الحدود المضمّنة.
- يتضمن التطبيق حقولاً مرجعية افتراضية موزعة على مناطق مصرية مختلفة.

## مصادر البيانات

### الطقس التاريخي

يستعلم التطبيق من **Open-Meteo Historical Weather API** للوصول إلى أرشيف إعادة التحليل **ERA5**. النموذج التاريخي محدد في الكود بالقيمة **historicalModel = 'era5'**.

تتضمن المتغيرات اليومية المطلوبة:

- درجة الحرارة العظمى على ارتفاع 2 متر (°C).
- درجة الحرارة الصغرى على ارتفاع 2 متر (°C).
- البخر نتح المرجعي وفق FAO (mm).
- مجموع الهطول (mm).

تُطلب البيانات بالتوقيت المحلي **Africa/Cairo**. ويأخذ مستودع الطقس في الحسبان تأخر إتاحة أرشيف ERA5 عند تحديد أحدث تاريخ تاريخي مؤهل.

### التوقعات

يستخدم التطبيق واجهة Open-Meteo Forecast للحصول على السجلات اليومية المتوقعة للمتغيرات نفسها. يجب التمييز دائماً بين التوقعات الجوية والسجل التاريخي المعاد تحليله؛ فهما مصدران مختلفان.

### بيانات الحدود الجغرافية

يضم المستودع ملف GeoJSON للحدود الإدارية المصرية ضمن assets/geo/. يستخدمه التطبيق للتحقق المكاني من موقع الحقل وتحديد المحافظة. ولا يعني ذلك أن بيانات الطقس نفسها مقاسة داخل حدود الحقل أو أنها بيانات محطة أرضية.

## المؤشرات والحسابات الزراعية

توجد الحسابات الزراعية في طبقة المجال (Domain)، منفصلة عن واجهات العرض.

### البخر نتح المرجعي ET₀

ET₀ هو البخر نتح المرجعي اليومي الذي توفره خدمة الطقس ضمن متغير FAO الخاص بها. يعرض التطبيق القيم اليومية ومجموع الفترة عندما تكون البيانات صالحة ومكتملة وفق سياسة التحقق.

### البخر نتح للمحصول ETc

يعتمد الحساب اليومي على العلاقة:

**ETc = Kc × ET₀**

حيث ET₀ البخر نتح المرجعي (mm/day)، وKc معامل المحصول للمرحلة النمائية، وETc البخر نتح للمحصول (mm/day).

يحسب التطبيق الاحتياج التراكمي عبر دورة النمو باستخدام معاملات Kc المرحلية المسجلة للمحصول. كما يحوّل عمق الماء من المليمتر إلى حجم لكل فدان باستخدام مساحة الفدان المعتمدة في ثوابت التطبيق (4200.83 م²؛ أي نحو 4.20083 م³ لكل 1 mm على فدان واحد).

**تنبيه:** ETc يمثل استهلاكاً مائياً تقديرياً للمحصول وفق المنهجية المستخدمة، ولا يساوي وحده كمية الري المطلوب إضافتها. تحديد الري الفعلي يتطلب عوامل إضافية مثل المطر الفعال، وكفاءة نظام الري، ورطوبة التربة، وظروف الحقل.

### أيام درجات النمو GDD

يحسب التطبيق مساهمة اليوم وفق صيغة درجات النمو، مع درجة أساس Tbase وإمكانية تطبيق حد أعلى Tcutoff:

**GDD = max(0, ((Tmax_adj + Tmin_adj) / 2) - Tbase)**

ويُجمع الناتج عبر الأيام بعد التحقق من بيانات درجات الحرارة.

### الإجهاد الحراري

يقارن مقيّم الإجهاد الحراري درجة الحرارة العظمى اليومية بالحد الحرج المسجل للمحصول، ثم يحسب عدد أيام التجاوز ونسبتها ويصنف مستوى الخطر إلى منخفض أو معتدل أو مرتفع أو حرج. التصنيف مرتبط بالحدود والمعاملات الموجودة في كتالوج المحاصيل، ويجب تفسيره في ضوء الصنف والمرحلة الفينولوجية والظروف المحلية.

### تقييم الدورة الزراعية

يحتوي التطبيق على كتالوج محاصيل ومعاملات مرجعية، ومسبقات (Presets) لتسلسلات زراعية، ومقيّم للدورة يخرج تقييماً وفق قواعد المجال المطبقة. هذه المخرجات تقييم إرشادي قائم على النموذج والبيانات المعرفة في التطبيق، وليست ضماناً للعائد أو خصوبة التربة في مزرعة بعينها.

## التحقق من البيانات والشفافية العلمية

يتعامل التطبيق صراحةً مع الفرق بين القيمة الصفرية والبيانات المفقودة:

- 0.0 قيمة رقمية فعلية (مثل عدم تسجيل هطول).
- null تعني أن القراءة غير متاحة، ولا تُستبدل بصفر.
- يتحقق محوّل Open-Meteo من وحدات المتغيرات المطلوبة قبل تحويل الاستجابة إلى سجلات المجال.
- تُفحص بنية المصفوفات اليومية واتساق السجلات والنطاقات الفيزيائية للمتغيرات.
- تحتفظ السجلات ببيانات المصدر (Provenance)، بما فيها اسم المزود ومجموعة البيانات والإحداثيات المطلوبة وإحداثيات خلية الشبكة ووقت الحصول على البيانات عند توفرها.
- تطبق الحسابات التي تتطلب سلسلة زمنية سياسة تحقق من نقص البيانات؛ وعند تجاوز حد النقص المسموح لا يصدر التطبيق نتيجة حسابية وكأن السلسلة مكتملة.
- تحافظ الرسوم البيانية على مواضع الأيام المفقودة بدلاً من اختلاق نقاط بديلة أو إزاحة الأيام اللاحقة.

## البنية التقنية

المشروع مبني باستخدام Flutter وDart، ويتبع فصلاً بين طبقات العرض والمجال والبيانات:

- **Presentation:** الشاشات وعناصر الواجهة والرسوم البيانية ومزودات حالة Riverpod.
- **Domain:** نماذج الحقول والمحاصيل والسجلات المناخية وواجهات المستودعات والتحقق والحسابات الزراعية.
- **Data:** مستودعات البيانات ومحولات Open-Meteo ومصادر البيانات البعيدة والمحلية والتخزين المؤقت.
- **Core:** الثوابت ومعالجة الأخطاء والنتائج والتحقق من النطاقات.

### أبرز الحزم

| الحزمة | الاستخدام |
|---|---|
| flutter_riverpod | إدارة الحالة والاعتماديات. |
| dio | طلبات HTTP لخدمات الطقس. |
| drift وsqlite3_flutter_libs | قاعدة بيانات SQLite والتخزين المحلي. |
| flutter_map وlatlong2 | الخريطة التفاعلية والإحداثيات. |
| fl_chart | الرسوم البيانية المناخية. |
| intl وflutter_localizations | تنسيق التواريخ والتوطين. |

### بنية مختصرة للمجلدات

```
lib/

  data/

  geo/                 # بيانات الحدود الجغرافية
ScreenShots/           # لقطات واجهة التطبيق
test/                  # الاختبارات
```

## التشغيل محلياً

### المتطلبات

- Flutter SDK متوافق مع قيد Dart في pubspec.yaml (Dart SDK ^3.13.2).
- بيئة تطوير تدعم المنصة المستهدفة.
- اتصال بالإنترنت لجلب بيانات Open-Meteo وعرض خرائط الأساس عند استخدامها.

### خطوات التشغيل

```bash
git clone https://github.com/AhmedKaram134679/AgroShift.git
cd AgroShift
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter run
```

يُستخدم build_runner لتوليد ملفات Drift عند الحاجة أو بعد تغييرات مخطط قاعدة البيانات.

### بناء Android

```bash
flutter build apk --release
```

### بناء Windows

```bash
flutter build windows --release
```

## الاختبارات والتحليل

```bash
flutter test
flutter analyze
```

توجد اختبارات وحدات وتكامل وواجهات تغطي أجزاء من محولات بيانات الطقس والتخزين المحلي والتحقق من الحدود الجغرافية والحسابات الزراعية وسلوك الواجهات وحالات نقص البيانات. لا تعتبر الأوامر أعلاه تقرير نجاح حديثاً؛ يجب تشغيلها على نسخة العمل الحالية للتحقق من الحالة الفعلية.

## القيود المعروفة

- دقة بيانات ERA5 مرتبطة بدقة شبكة إعادة التحليل وموقع خلية الشبكة؛ الإحداثيات المطلوبة للحقل قد تختلف عن إحداثيات الخلية التي أعادتها الخدمة.
- إعادة التحليل ليست قياساً مباشراً داخل الحقل، كما أن التوقعات ليست سجلات تاريخية.
- معاملات المحاصيل قيم مرجعية، وقد تحتاج معايرة محلية بحسب الصنف والمنطقة والموسم والإدارة الزراعية.
- لا يحسب ETc وحده صافي أو إجمالي مياه الري الواجب ضخها.
- لا ينبغي اعتبار تقييم الدورة الزراعية أو تحذيرات الإجهاد توصية ميدانية نهائية دون تحقق محلي.
- توفر بيانات الطقس والخرائط يعتمد على الخدمات الخارجية والاتصال بالإنترنت.
